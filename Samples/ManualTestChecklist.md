# Чек-лист ручного тестирования редактора

## Общие предусловия
- Запустить приложение, убедиться что окно открылось и статусбар отображает состояния.
- Для сценариев с файлами использовать отдельную тестовую папку.

---

## 1) Команды форматирования B / I / U / S

### Базовые проверки
- [ ] **Bold (B / Ctrl+B):** без выделения включает режим набора жирным; с выделением переключает только выделенный фрагмент.
- [ ] **Italic (I / Ctrl+I):** аналогично Bold.
- [ ] **Underline (U / Ctrl+U):** добавляет/снимает underline, не ломая другие decorations.
- [ ] **Strikethrough (S / Ctrl+Shift+X):** добавляет/снимает strike, не ломая underline.
- [ ] Toggle-кнопки корректно отражают состояние при перемещении курсора по тексту.

### Edge cases
- [ ] Смешанное выделение (часть жирная, часть нет): состояние кнопки не приводит к потере других стилей.
- [ ] Комбинации underline + strike: отключение одного не удаляет второй.
- [ ] Пустой документ: команда не падает.

---

## 2) Выравнивание (L/C/R)

### Базовые проверки
- [ ] **AlignLeft / AlignCenter / AlignRight** применяются к текущему абзацу при пустом выделении.
- [ ] При выделении нескольких абзацев выравнивание применяется ко всем.
- [ ] Активна ровно одна кнопка выравнивания по текущему положению курсора.

### Edge cases
- [ ] Курсор на границе абзацев (начало/конец) — состояние выравнивания корректно.
- [ ] После undo/redo индикатор активной кнопки синхронизируется.

---

## 3) Tab / Shift+Tab (TextIndent)

### Базовые проверки
- [ ] Tab увеличивает `TextIndent` текущего абзаца.
- [ ] Shift+Tab уменьшает `TextIndent`.
- [ ] При выделении нескольких абзацев отступ меняется у всех.
- [ ] Фокус не уходит с RichTextBox при Tab.

### Edge cases
- [ ] Отступ не уходит в минус (нижняя граница 0).
- [ ] Выделение и позиция курсора сохраняются после изменения отступа.

---

## 4) Undo / Redo

### Базовые проверки
- [ ] Undo (Ctrl+Z / кнопка ↶) откатывает последние изменения.
- [ ] Redo (Ctrl+Y и Ctrl+Shift+Z / кнопка ↷) возвращает действие.
- [ ] Кнопки disable/enable в соответствии с `CanUndo`/`CanRedo`.
- [ ] Статусбар показывает актуальную доступность undo/redo.

### Edge cases
- [ ] После новой правки redo-стек сбрасывается.
- [ ] Undo/Redo после форматирования, выравнивания, tab-отступов.

---

## 5) Сноски

### Базовые проверки
- [ ] Кнопка `[?]` вставляет маркер в позиции курсора.
- [ ] В конце документа создаётся/обновляется секция `Сноски`.
- [ ] Нумерация автоинкрементная.
- [ ] Клик по маркеру переходит к записи сноски и обратно (bidirectional navigation).

### Edge cases
- [ ] Удаление маркера + вызов перенумерации: номера в тексте и списке синхронны.
- [ ] Несколько сносок подряд, вставка в середину документа.

---

## 6) Divider (разделитель)

### Базовые проверки
- [ ] Кнопка `—` вставляет отдельный параграф-разделитель с нужным стилем.
- [ ] После вставки каретка ставится в следующий обычный абзац.

### Edge cases (атомарность)
- [ ] Backspace/Delete на divider удаляет весь divider-параграф целиком.
- [ ] Backspace в начале следующего абзаца удаляет предыдущий divider.
- [ ] Delete в конце предыдущего абзаца удаляет следующий divider.

---

## 7) Типографика

### Базовые проверки
- [ ] Автозамена текстовых дефисов/тире работает.
- [ ] Числовые диапазоны типа `10-12` и `10 - 12` не ломаются.
- [ ] Вложенные кавычки нормализуются по схеме `«уровень 1 “уровень 2”»`.

### Edge cases
- [ ] На кодовых фрагментах (стиль/тег Code) типографика не применяется.
- [ ] Повторные правки не приводят к циклической порче текста.

---

## 8) Импорт DOCX

### Базовые проверки
- [ ] `Ctrl+O` / кнопка `Импорт DOCX` открывают диалог выбора файла.
- [ ] После импорта загружаются абзацы, базовые run-стили (B/I/U/S), выравнивание.
- [ ] Гиперссылки (если есть в DOCX) импортируются без падений.
- [ ] Таблицы импортируются в стабильном «плоском» представлении (строки через `|`).

### Edge cases
- [ ] Пустой/повреждённый DOCX: показывается ошибка, приложение не падает.
- [ ] Очень большой DOCX: UI остаётся отзывчивым (хотя операция может быть долгой).

---

## 9) Экспорт (TXT / HTML / DOCX / PDF-plan)

### TXT
- [ ] Экспортирует plain text содержимое.
- [ ] UTF-8, кириллица без кракозябр.

### HTML
- [ ] Формирует валидный базовый HTML (`p`, `strong`, `em`, `u`, `s`, `a`, `br`).
- [ ] Сохраняет paragraph alignment.
- [ ] Для документов после DOCX-импорта срабатывает sanitize (без лишних inline-стилей и неподдерживаемых тегов).

### DOCX
- [ ] Сохраняются базовые стили B/I/U/S, выравнивание, first-line indent.
- [ ] Divider и секция `Сноски` экспортируются как обычные абзацы в конце.
- [ ] Экспортированный DOCX открывается в Word/LibreOffice без ошибок.

### PDF
- [ ] Ветка PDF показывает понятное сообщение о нереализованности и плане действий.

### Edge cases
- [ ] Отмена SaveFileDialog не вызывает исключений.
- [ ] Перезапись существующего файла работает корректно.

---

## 10) Dirty flag / закрытие / автосохранение / восстановление

### Базовые проверки
- [ ] После правок title содержит `*`, статус: `Изменения: не сохранены`.
- [ ] После сохранения `*` исчезает, статус: `Изменения: сохранены`.
- [ ] При закрытии с несохранёнными изменениями показывается `Yes/No/Cancel`.
- [ ] Автосохранение создаёт temp-файл каждые N секунд при dirty-документе.
- [ ] При следующем запуске предлагается восстановление автосохранения.

### Edge cases
- [ ] Выбрать `Cancel` на закрытии — окно не закрывается.
- [ ] Выбрать `Yes`, затем отменить SaveDialog — закрытие отменяется.
- [ ] При `No` закрытие продолжается без сохранения.
- [ ] Ошибка чтения autosave-файла даёт warning, приложение продолжает работу.
